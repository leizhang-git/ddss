## 一、数据库初始化脚本（ddss.sql）

`db/ddss.sql` 是**可重复执行的幂等全量初始化脚本**。

### 关键约定
- 脚本开头会执行：`DROP DATABASE IF EXISTS \`ddss\`` → `CREATE DATABASE \`ddss\`` → `USE \`ddss\``。
- 因此**每次执行都会先删库、再建库、再建表、再灌数据**，无论执行多少次结果一致，不会报错。
- 所有表均带 `DROP TABLE IF EXISTS`（共 37 张表，每张表都有对应 DROP）。
- 脚本开头 `SET FOREIGN_KEY_CHECKS = 0;`（建表顺序无关），结尾 `SET FOREIGN_KEY_CHECKS = 1;` 恢复。
- 数据库字符集：`utf8mb4` / `utf8mb4_0900_ai_ci`，库名：`ddss`。
- **权限要求**：需要具备 `DROP / CREATE DATABASE` 权限，建议用 root 或具备该权限的账号执行。

### 涉及的功能表
| 表面 | 说明 |
|------|------|
| `ddss_resource` | 资源管理表（上传文件元数据） |
| `ddss_video` | 视频管理表 |
| `ddss_leave` | 请假申请单（工作流演示） |
| `ddss_flow_design` | 流程模型/设计器（工作流 BPMN） |
| `sys_*` | 系统基础表（用户/角色/菜单/部门/字典/配置/岗位/日志/调度等 RuoYi 体系） |
| `gen_table` / `gen_table_column` | 代码生成器元数据 |
| `qrtz_*` | Quartz 定时调度表 |
| `sys_finance` | 财务数据表 |
| `sys_video_resource` | 视频资源表 |
| `sys_sql_record` | SQL 执行记录（中间件监控） |

### 执行方式
直接整文件执行即可（可反复执行）。示例：
```bash
mysql -u root -p < db/ddss.sql
```

## 二、项目整体结构

基于 **RuoYi v3.9.0** 改造，技术栈：**Spring Boot 2.5.15 + Vue 2 + Element UI**。

| 模块 | 说明 |
|------|------|
| `ddss-bootstrap` | Spring Boot 入口 + REST Controller + Swagger + 中间件开关 |
| `ddss-common` | 工具类、注解、常量、过滤器、设计模式基类 |
| `ddss-ry-framework` | Security/JWT/AOP、Event 系统、Strategy 实现、线程池 |
| `ddss-system` | 系统业务：用户/角色/菜单/部门/字典/配置等 |
| `ddss-server` | 业务模块：财务管理、视频资源、Kafka、MinIO、工作流 |
| `ddss-quartz` | 定时任务管理 |
| `ddss-generator` | 代码生成器 |
| `ddss-ui` | 前端 Vue2 + Element UI + ECharts |

### 数据库连接
- **MySQL（默认）**：`ddss` 库，配置见 `ddss-bootstrap/src/main/resources/application-local.yml`。
- **H2 内存库（降级）**：当中间件 `mysql.enabled=false` 时自动切 H2，执行
  `ddss-bootstrap/src/main/resources/h2/schema.sql` + `h2/data.sql`。

### 中间件开关（`bootstrap.yml` 中 `ddss.middleware.*`）
`nacos` / `redis` / `kafka` / `minio` / `mysql` / `xxl-job` 均可开关；
MySQL 关闭时自动切 H2 内存库。开发认证后门：`ddss.dev.login-enabled`。

## 三、工作流模块（本轮新功能，简记）

- 后端新代码：`ddss-server/src/main/java/com/ddss/server/workflow/`
- 流程设计器 Controller：`ddss-bootstrap/src/main/java/com/ddss/web/controller/workflow/`
- PO / Mapper：`DdssFlowDesign`、`DdssLeave`（含对应 Mapper）
- BPMN 资源：`ddss-server/src/main/resources/processes/`、`resources/model/`
- 前端：`ddss-ui/src/views/workflow/`、`ddss-ui/src/api/workflow.js`、`workflowModel.js`
- 数据库：`ddss_flow_design`（流程模型）、`ddss_leave`（请假单）

### 工作流模块的「配置页面」入口（重要）
左侧菜单 **工作流** 目录下（菜单根 id=3012）：
| 菜单 | 路径 | 说明 |
|------|------|------|
| 请假申请 | `workflow/leave/index` | 发起请假 |
| 待办审批 | `workflow/todo/index` | 审批待办 |
| 流程定义 | `workflow/definition/index` | 已部署 BPMN |
| **流程管理（配置/设计页面）** | `workflow/model/index` | 新建/导入/编辑/发布/删除流程模型 |

「流程管理」页面点新建/编辑会进入流程设计器 `workflow/model/designer`（路由 `/workflow/model-edit`）。
流程管理菜单 id=3021，于 2026-08-19 加入，需**重新执行初始化脚本并重新登录**才会在侧边栏出现。
权限：role 1（admin）拥有全部 workflow 菜单(3012-3026)；role 2 有 3012-3015、3021 但**缺少子按钮权限 3016-3020、3022-3026**（看不到新增/编辑等按钮）。
菜单种子数据同时存在于 `db/ddss.sql`（MySQL）与 `h2/data.sql`（H2 模式）。

### 流程设计器（designer.vue）数据流要点
- 后端 `/workflow/model/{id}/xml` 返回 `AjaxResult.success(xml)` → JSON `{code,msg,data}`。
- 前端 `@/api/workflowModel.js` 的 `getModelXml()` 走 RuoYi request 拦截器，返回的是**整个响应体对象**（不是裸 XML）。
- **务必取 `.data` 再传给 `importXML`**！漏取 `.data` 会导致画布无有效 BPMN 根，palette 节点「拖不动」。
  - 正确写法：`const xml = (await getModelXml(this.modelId)).data`
- 新建模型时后端用 `model/template.bpmn20.xml`（含开始/审批/结束 3 节点 + DI）作为默认 XML。
