## 一、数据库初始化脚本（ddss.sql）

`db/ddss.sql` 是**可重复执行的幂等全量初始化脚本**。

### 关键约定
- 脚本开头会执行：`DROP DATABASE IF EXISTS \`ddss\`` → `CREATE DATABASE \`ddss\`` → `USE \`ddss\``。
- 因此**每次执行都会先删库、再建库、再建表、再灌数据**，无论执行多少次结果一致，不会报错。
- 所有表均带 `DROP TABLE IF EXISTS`（共 37 张表，每张表都有对应 DROP）。
- 脚本开头 `SET FOREIGN_KEY_CHECKS = 0;`（建表顺序无关），结尾 `SET FOREIGN_KEY_CHECKS = 1;` 恢复。
- 数据库字符集：`utf8mb4` / `utf8mb4_0900_ai_ci`，库名：`ddss`。
- **权限要求**：需要具备 `DROP / CREATE DATABASE` 权限，建议用 root 或具备该权限的账号执行。
- **既有库升级**：全量脚本会重建数据库，不能用于保留现有数据的升级。请先备份，再手工执行 `db/migration/V20261012_01__leave_days_decimal.sql`，将 `ddss_leave.leave_days` 改为 `DECIMAL(4,1)`；当前没有自动 migration runner。

### 涉及的功能表
| 表面 | 说明 |
|------|------|
| `ddss_resource` | 资源管理表（上传文件元数据） |
| `ddss_video` | 视频管理表 |
| `ddss_leave` | 请假申请单（工作流演示） |
| `ddss_flow_design` | 流程模型/设计器（工作流 BPMN） |
| `sys_*` | 系统基础表（用户/角色/菜单/部门/字典/配置/岗位/日志/调度等 RuoYi 体系） |
| `gen_table` / `gen_table_column` | 代码生成器元数据 |
| `qrtz_*` | Quartz 定时调度表 |
| `sys_finance` | 财务数据表 |
| `sys_video_resource` | 视频资源表 |
| `sys_sql_record` | SQL 执行记录（中间件监控） |

### 执行方式
直接整文件执行即可（可反复执行）。示例：
```bash
mysql -u root -p < db/ddss.sql
```

## 二、项目整体结构

基于 **RuoYi v3.9.0** 改造，技术栈：**Java 17 + Spring Boot 2.5.15 + Vue 2 + Element UI**。当前根 POM 聚合七个后端模块；`ddss-parent` 是根 POM，`ddss-ui` 为独立前端项目。新建的 `ddss-domain` / `ddss-application` 是 framework-free 的工作流请假发起/审批/本人批量撤回/流程定义批量删除与 Finance 导出计算领域/用例切片，已通过 provider 适配器接入对应业务路径；没有替换其余既有 Flowable 能力或 Finance CRUD/统计实现。

| 模块 | 当前实现 |
|------|------|
| `ddss-bootstrap` | Spring Boot 入口 + 组装层：登录/注册/首页、验证码、通用及监控 REST、Nacos 配置/发现、中间件开关 |
| `ddss-common` | 工具类、注解、常量、过滤器、Redis 缓存封装；依赖含 Spring Web/Security、Redis、PageHelper、POI 等，不是无基础设施依赖的纯工具模块 |
| `ddss-framework` | Security/JWT/AOP、Event、验证码 Strategy、线程池、Kafka、MinIO、XXL-Job 等框架支持 |
| `ddss-domain` | framework-free 请假申请与 Finance 导出计算领域类型（不可变申请/天数、FinanceLoan/Schedule/Status）及领域测试；不是所有业务实体的统一归属 |
| `ddss-application` | framework-free `SubmitLeave`、`DecideWorkflowTask`、`WithdrawLeaveApplications`、`DeleteWorkflowDeployments` 与 `PrepareFinanceExport` 用例、出站端口/导出计划，依赖 domain；provider 通过 MyBatis/Flowable/Finance 适配器装配 |
| `ddss-consumer` | system/finance/video 域的实体、Service 接口与 Mapper 接口；既有工作流类型仍在 provider |
| `ddss-provider` | system/finance/video 业务实现与 REST Resource；既有工作流的 domain/mapper/service 接口和实现、Flowable、Mapper XML、quartz、代码生成、MinIO 资源同步任务 |
| `ddss-ui` | Vue 2 + Element UI + ECharts 前端 |

**当前分层边界**：新增依赖为 `application → domain`，provider 增加 `provider → application + domain` 依赖，并将请假发起、审批、本人批量撤回、流程定义批量删除命令与 Finance 导出准备接入 application 用例；既有 Maven 依赖为 `consumer → common`、`framework → consumer`、`provider → consumer + framework`、`bootstrap → framework + provider`。工作流请假发起服务调用 `SubmitLeave`，审批服务调用 `DecideWorkflowTask`，批量撤回服务调用 `WithdrawLeaveApplications`，定义删除服务调用 `DeleteWorkflowDeployments`；provider 适配器封装 MyBatis 持久化与 Flowable 流程/任务操作；待办/已办查询、模型管理和其余工作流服务仍主要沿用 provider 既有实现。业务 REST Resource 在 provider；认证、通用、验证码、首页和监控 REST 在 bootstrap。consumer 可以独立构建，但当前尚未以 RPC 替代 REST；RPC 发布/调用仍属后续选项。

### 数据库连接
- **MySQL（默认）**：`ddss` 库，配置见 `ddss-bootstrap/src/main/resources/application-local.yml`。
- **H2 内存库（降级）**：当中间件 `mysql.enabled=false` 时自动切 H2，执行
  `ddss-bootstrap/src/main/resources/h2/schema.sql` + `h2/data.sql`。

### 中间件开关（`ddss-bootstrap/src/main/resources/bootstrap.yml` 中 `ddss.middleware.*`）
`nacos` / `redis` / `kafka` / `minio` / `mysql` / `xxl-job` 均可开关；
MySQL 关闭时自动切 H2 内存库。开发认证后门：`ddss.dev.login-enabled`，开启后无 token 请求可按 admin 身份放行，只能用于本地开发。

### 后端构建与测试验证

仓库未包含 Maven Wrapper。使用本机已安装 Maven，从项目根目录运行：

```bash
mvn clean verify
```

该命令会构建根 POM 聚合的所有模块并运行测试，包括领域、application、provider Finance/workflow 适配器与 workflow 合约测试。若只验证 `ddss-application` 及其 `ddss-domain` 依赖模块：

```bash
mvn -pl ddss-application -am test
```

只运行 provider 的计算器测试及所需 reactor 依赖模块：

```bash
mvn -pl ddss-provider -am -Dtest=FinanceScheduleCalculatorTest,PrepareFinanceExportTest,SubmitLeaveTest,DecideWorkflowTaskTest,WithdrawLeaveApplicationsTest,DeleteWorkflowDeploymentsTest,WorkflowTaskQueriesTest,LegacyFinanceExportAdapterTest,FinanceExportMigrationTest,LegacyLeaveAdaptersTest,LegacyLeaveWithdrawalAdapterTest,LegacyWorkflowDeploymentDeletionAdapterTest,LegacyWorkflowApprovalAdapterTest,LegacyWorkflowTaskQueryAdapterTest,WorkflowServiceContractTest -Dsurefire.failIfNoSpecifiedTests=false test
```

若已安装 Maven 3.9.9（Windows/Git Bash），可用 README 示例的 `/d/apache-maven-3.9.9/bin/mvn.cmd` 替代 `mvn`。

## 三、工作流模块（当前源码位置）

- 现有 Flowable 后端实现（domain、mapper、service 接口/实现、REST Resource）：`ddss-provider/src/main/java/com/ddss/workflow/`；新建的 framework-free 申请类型与用例位于 `ddss-domain/src/main/java/com/ddss/domain/workflow/` 和 `ddss-application/src/main/java/com/ddss/application/workflow/`，通过 `ddss-provider/src/main/java/com/ddss/workflow/adapter/` 中的适配器接入请假发起、审批、本人批量撤回、流程定义批量删除命令及待办/已办查询。模型管理和其余工作流能力仍由既有 provider 服务处理。Finance 导出计算领域和用例分别位于 `ddss-domain/.../finance/`、`ddss-application/.../finance/`，provider 的 `finance/adapter/` 负责旧 PO/JSON 映射，REST Resource 负责 POI 输出；CRUD、统计和页面本地计算尚未迁移。
- 工作流 REST Resource：`ddss-provider/src/main/java/com/ddss/workflow/web/rest/`
- PO / Mapper：`DdssFlowDesign`、`DdssLeave` 及 Mapper，位于 provider 的 `domain/`、`mapper/`；当前不在 consumer 契约包。
- BPMN 资源：`ddss-provider/src/main/resources/processes/`、`ddss-provider/src/main/resources/model/`
- 流程设计器相关 REST Controller 也由 provider 的 `WorkflowModelResource` 等处理；bootstrap 下没有 `web/controller/workflow/` 路径。
- 前端：`ddss-ui/src/views/workflow/`、`ddss-ui/src/api/workflow.js`、`workflowModel.js`
- 数据库：`ddss_flow_design`（流程模型）、`ddss_leave`（请假单）

### 工作流模块的「配置页面」入口（重要）
左侧菜单 **工作流** 目录下（菜单根 id=3012）：
| 菜单 | 路径 | 说明 |
|------|------|------|
| 请假申请 | `workflow/leave/index` | 发起请假 |
| 待办审批 | `workflow/todo/index` | 审批待办 |
| 流程定义 | `workflow/definition/index` | 已部署 BPMN |
| **流程管理（配置/设计页面）** | `workflow/model/index` | 新建/导入/编辑/发布/删除流程模型 |

「流程管理」页面点新建/编辑会进入流程设计器 `workflow/model/designer`（路由 `/workflow/model-edit`）。
流程管理菜单 id=3021，于 2026-08-19 加入，需**重新执行初始化脚本并重新登录**才会在侧边栏出现。
权限：role 1（admin）拥有全部 workflow 菜单(3012-3026)；role 2 有 3012-3015、3021 但**缺少子按钮权限 3016-3020、3022-3026**（看不到新增/编辑等按钮）。
菜单种子数据同时存在于 `db/ddss.sql`（MySQL）与 `h2/data.sql`（H2 模式）。

### 流程设计器（designer.vue）数据流要点
- 后端 `/workflow/model/{id}/xml` 返回 `AjaxResult.success(xml)` → JSON `{code,msg,data}`。
- 前端 `@/api/workflowModel.js` 的 `getModelXml()` 走 RuoYi request 拦截器，返回的是**整个响应体对象**（不是裸 XML）。
- **务必取 `.data` 再传给 `importXML`**！漏取 `.data` 会导致画布无有效 BPMN 根，palette 节点「拖不动」。
  - 正确写法：`const xml = (await getModelXml(this.modelId)).data`
- 新建模型时后端用 `model/template.bpmn20.xml`（含开始/审批/结束 3 节点 + DI）作为默认 XML。

## 四、常用操作速查

- 前端开发目录：`ddss-ui`；启动前先 `npm install`。
- 后端入口模块：`ddss-bootstrap`。
