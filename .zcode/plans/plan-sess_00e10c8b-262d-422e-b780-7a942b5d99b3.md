## 目标
把当前 DDSS 工程从“大规模模块迁移中的工作区”收敛成一个可编译、可启动、可回归、可继续演进的工程；优化重点不是机械格式化，而是安全基线、架构边界、统一契约、并发/缓存正确性、前端工程化和可验证性。

我不会覆盖或回滚现有未提交改动，也不会直接把所有文件重写一遍。当前工作区已经有一轮很大的 consumer/provider/bootstrap 重构：约 305 个变更条目，约 2.5 万行删除，新模块中还有未跟踪文件。因此第一步必须先把迁移闭环，再做高阶优化。

## 已确认的关键问题

- **迁移基线未闭环**：旧模块大量删除，新 `ddss-consumer`、`ddss-provider` 和部分 framework 文件仍是未跟踪状态；旧包名在契约、任务白名单、配置和框架代码中有兼容性残留，不能机械全局替换。
- **P0 安全问题**：`bootstrap.yml` 中 `ddss.dev.login-enabled` 当前默认值为 `true`，`JwtAuthenticationTokenFilter` 的 `@Value` 默认值也为 `true`；本地配置还包含数据库、Redis、MinIO、Druid、JWT 等明文凭据/地址。
- **响应契约并存**：新 `R<T>` 已加入 traceId，但大量 REST 和全局异常处理仍返回旧 `AjaxResult`，错误响应还同时出现 `vtrace` 与 `traceId` 两套表达。
- **全链路细节需要收口**：TraceId 入站值没有长度/字符校验；`EventPublisher` 把 HttpServletRequest 对象带进异步事件；`LogAspect` 与新的 logging aspect 并存，存在重复记录和行为分叉风险；线程池属性同时使用 `@ConfigurationProperties` 和 `@Value`。
- **缓存并发问题**：`RedisCache` 的互斥锁释放没有持有者 token 校验，可能误删其他线程的锁；未命中重试通过递归和固定 sleep 实现，边界和压力下不够稳。
- **业务计算问题**：`FinanceCalculator` 使用 `double` 做金额比较/计算，并在内部调用 `LocalDate.now()` 推断月份，难以单测且跨年边界不稳定；财务统计服务多次全表加载并返回弱类型 Map。
- **分页/接口风格未统一**：大量资源仍使用 `startPage()`，异常路径可能遗留 PageHelper ThreadLocal；新旧返回类型、命名和错误处理风格混用。
- **前端工程化缺口**：约 32k 行 Vue2 源码、62 个页面、27 个 API 模块，没有 lockfile、lint、格式化、单测、E2E 或 CI；`vue.config.js` 硬编码后端地址且开启 `disableHostCheck`；请求层、动态路由、多个页面存在吞错/loading 不回收等问题。
- **前端安全/稳定性线索**：存在 `v-html`、`dangerouslyUseHTMLString`、编辑器 HTML 注入、前端打包 RSA 私钥、文件上传模板字符串疑似错误、全局事件未清理等高风险点。

## 分阶段实施方案

### 阶段 0：建立可回滚、可验证基线

1. 保留现有工作树，不做 reset、不做覆盖式清理、不擅自 commit。
2. 记录迁移基线：模块清单、POM 依赖图、旧包引用、未跟踪文件、资源路径和配置入口，形成一份简短的工程基线文档。
3. 验证新五模块闭环：`common -> consumer -> framework -> provider -> bootstrap`，清理真实的旧模块依赖，保留确实用于 URL/配置/任务兼容的历史名称。
4. 校验 MyBatis mapper 资源扫描、Flowable BPMN 资源、代码生成模板和 Spring 组件扫描；重点检查当前 provider 中的 mapper 资源路径是否与 `classpath*:mapper/**/*Mapper.xml` 一致。
5. 第一轮只做构建/启动验证：后端使用 H2 + 关闭中间件的开发 profile，前端使用现有构建脚本；先得到真实失败清单，再按失败根因修复。

**门禁**：后端 `mvn -pl ddss-bootstrap -am compile` 通过；前端生产构建通过；`git diff --check` 无新增问题；H2 模式能够启动并完成基础登录/路由请求。

### 阶段 1：P0 安全与配置治理

1. 将开发认证后门默认值统一改为 `false`，过滤器、配置文件、文档和启动告警保持一致；只有明确的本地 profile 才能开启，并在非开发 profile 下 fail-fast。
2. 把数据库、Redis、MinIO、Druid、JWT、Nacos、XXL-Job 等敏感值改为环境变量/Nacos 密文占位符；保留 `application-local.example.yml` 形式的示例，不再在可运行配置中放真实口令。
3. 把中间件开关收敛为类型化配置对象，明确默认值和 profile 优先级；MySQL/H2 切换、Redis/Kafka/MinIO/XXL-Job 条件装配统一走同一套配置语义。
4. 移除 `disableHostCheck: true`，改为可配置的开发允许主机列表；后端 CORS、白名单、Druid 暴露路径同步做最小权限收口。
5. 前端移除打包进浏览器的 RSA 私钥，只允许公开密钥或服务端下发的公钥参与加密；检查所有 `v-html`/`dangerouslyUseHTMLString`/HTML 高亮输入，默认转义，确需 HTML 时使用白名单清洗。
6. 复核文件上传、MinIO 路径、下载和压缩包处理，阻断路径穿越、任意文件名和不受控内容类型。

**门禁**：静态扫描不再出现可运行配置中的明文凭据；默认启动不能无 token 访问业务接口；前端包中不存在私钥材料；安全相关单测覆盖默认拒绝和输入边界。

### 阶段 2：后端内核收口

1. **统一响应契约**：以 `R<T>` 为新接口标准，保留 `AjaxResult` 作为明确标记的兼容适配层；统一序列化为 `code/msg/data/traceId`，逐步移除 `vtrace` 重复字段，不一次性破坏旧前端。
2. **统一异常处理**：全局异常处理器覆盖认证、权限、参数、报文、业务和未知异常；业务错误使用 `ErrorCode`，未知异常只返回安全提示，日志按 traceId 记录完整 cause 链；补充 HTTP 状态/业务码契约测试。
3. **强化链路追踪**：TraceId 入站只接受受限长度和安全字符，非法值重新生成；响应头、响应体、MDC、异步线程使用同一 ID；事件对象改为不可变的请求快照，不再把 HttpServletRequest 直接传给异步监听器。
4. **合并日志切面**：确认 `LogAspect` 与 `aop.logging.LoggingAspect` 的职责，保留一条明确链路，避免操作日志重复写入；敏感字段过滤、请求体长度限制、异常路径 ThreadLocal 清理统一处理。
5. **线程池配置类型化**：去掉 `@ConfigurationProperties` 与 `@Value` 的重复绑定，增加范围校验、命名拒绝策略和优雅关闭；确保 `open_flag` 要么真正控制装配，要么移除误导性配置。
6. **Redis 正确性升级**：改为泛型 `RedisTemplate<String,Object>`；锁值使用随机 token，Lua 比较后删除；重建缓存使用有限次数、退避和中断传播；SCAN 使用明确编码，彻底隔离 `KEYS` 生产路径。
7. **分页统一出口**：把 system/quartz/generator/video/workflow 的列表接口逐步迁移到 `pageQuery`，保证成功、异常、空结果都清理 PageHelper ThreadLocal；保留旧接口结果字段不变。
8. **金额和领域规则**：`FinanceCalculator` 注入 `Clock` 或明确的 `YearMonth`，全部金额计算使用 `BigDecimal.compareTo`/明确舍入；修复跨年月份解析和还款区间边界；将财务汇总改为强类型 DTO，并减少重复全表读取。
9. **业务热点治理**：审查 workflow、quartz、generator、MinIO 同步任务的事务边界、批量查询、异常吞掉、文件路径和反射调用白名单；对批量删除返回真实影响行数，避免以输入数组长度冒充数据库结果。

**门禁**：common/framework/provider 单测通过；财务金额、跨年、空数据、缓存锁竞争、分页清理、异常响应和 traceId 测试通过；后端无新增旧式 `startPage()`/`AjaxResult` 使用点（兼容层除外）。

### 阶段 3：前端请求、状态和页面质量

1. 建立 `package-lock.json`，补齐 lint/format/unit test 脚本和 Vue2 兼容的工具链；不升级 Vue 大版本，先保证低风险可落地。
2. 重构 `src/utils/request.js`：一次读取 token、统一错误对象、统一 blob 错误解析、响应头 traceId 透传、重复提交 key 使用明确生命周期，避免 `Promise.reject` 被吞和 loading 泄漏。
3. 简化 `store/modules/user.js` 的手写 Promise，保证登录失败/退出失败都能清理状态；动态路由生成失败可重试，避免重复 `addRoutes` 和无限跳转。
4. 把财务页面中的计算/日期规则抽到纯函数模块，修正 `pageSize=999`、保存失败静默吞错、统计并发请求无统一 loading/catch 等问题。
5. 对 middleware、tool/build、system user/role、workflow 等大页面做低风险拆分：抽取请求、校验、表格列和对话框逻辑，先减少副作用，再考虑视觉增强。
6. 修复文件上传/ImageUpload 模板字符串、Settings 定时器立即执行、iFrame/拖拽/resize 全局事件未清理等生命周期问题。
7. `vue.config.js` 改为环境变量驱动的后端 target，移除硬编码地址和不安全 host 检查；保留现有代码分割并根据构建产物调整 chunk。

**门禁**：`npm run lint`、核心纯函数单测、`npm run build:prod` 通过；401/500/blob/网络异常/重复提交有可复现测试；关键页面失败时 loading 必须回收。

### 阶段 4：测试、CI 和工程表达

1. 后端补齐 JUnit/Spring Boot 测试：`FinanceCalculator`、`TraceIdFilter`、`GlobalExceptionHandler`、`RedisCache` 锁语义、H2 初始化、权限/分页边界。
2. 前端补齐请求层、路由权限、财务计算和关键校验的单测；对登录、动态路由、文件上传、工作流设计器建立最小黑盒回归清单。
3. 增加单一验证入口：后端 `clean verify`、前端 lint/unit/build、配置扫描和 diff 检查；如仓库托管平台适配，再补 CI 工作流，不把外部服务绑定到本地开发。
4. 更新 README/设计文档：模块依赖、开发 profile、密钥外置、测试命令、响应契约、H2 启动方式和安全红线必须与代码一致。
5. 增加 `.editorconfig`/必要的格式边界，避免继续扩大 LF/CRLF 和无意义全文件变更；不对现有文件做无收益的全量格式化。

## 执行顺序与交付方式

- 先执行阶段 0，修复会阻断编译/启动的迁移问题；然后阶段 1 的安全 P0；再按阶段 2、3、4 分批落地。
- 每一批只改相关文件，完成后立即运行对应门禁；不擅自提交 Git，保留所有改动供 review。
- 优先交付“可编译 + 默认安全 + 契约稳定 + 核心计算正确 + 有测试”的版本，再做可选的视觉/性能炫技，避免用大规模重写制造不可验证的风险。
- 最终验收以：后端构建、H2 启动、核心接口回归、前端 lint/unit/build、敏感配置扫描和工作区 diff 检查全部通过为准。
